# TENN — Tool-Extensible Node Notation

[English version](README.md)

TENN — текстовое представление деревьев команд с литеральными аргументами. Это **компактный
протокол**: текст достаточно короткий, чтобы человек писал его руками, достаточно регулярный, чтобы
инструмент читал его без схемы, и достаточно выразительный для диаграммы, документа, конфигурации или
вызова MCP-инструмента.

Одно правило грамматики:

```
command := name argument* block?
block   := { command* }
```

Схемы нет. Зарезервированных слов нет. Смысл придаёт потребитель: `element "Screen" { item A { pos 0 0 } }` —
это диаграмма, `service api { port 8080 }` — конфигурация, `set "item A" title "Hello"` — вызов
инструмента. Один парсер на всё.

```
element "Screen" {
    item A { pos 0 0 }
    item B { pos 320 0 }
    link A B
}
```

## Зачем

Большинство форматов обмена заставляют выбирать: либо жёсткая схема (быстро проверяется, больно
расширяется), либо свободный JSON (легко расширяется, многословен и нечитаем во вложенности). TENN
берёт форму Tcl — имя, аргументы и тело в фигурных скобках — и на этом останавливается.

- **Расширяется добавлением команд.** Не нужно ничего резервировать, нет реестра, который надо
  обновлять. Инструмент, который понимает `ports`, игнорирует `owners`, а файл, написанный для нового
  инструмента, всё равно разбирается старым.
- **Компактен.** Ни кавычек вокруг имён, ни запятых, ни скобок: набросок экрана или карта мыслей —
  это несколько сотен байт, а не несколько тысяч.
- **Удобен для diff.** Одна команда на строку, отступы — только представление, `git diff` показывает,
  что изменилось.
- **Безопасен для чтения.** При разборе ничего не выполняется. Выражения живут внутри `${...}` и
  вычисляются потребителем, а не парсером.
- **Одна реализация для портирования.** Весь синтаксис — лексер, рекурсивный парсер и принтер,
  несколько сотен строк на язык; поэтому здесь сосуществуют реализации на Go, TypeScript и Swift.

Для MCP-инструмента TENN — естественное тело запроса и ответа: `edit path "x.tenn"`, `set prop value`,
`run check`, а `{}`-блок задаёт список операций. Для документов команда называет раздел, а литерал
`%{...}` несёт его markdown-тело. Один файл может содержать и то, и другое.

## Девять видов значений

Аргумент — одно из девяти значений; это вся модель данных:

| Вид | Пример | Смысл |
|-----|--------|-------|
| `Ident` | `color red` | голое слово |
| `IntLit` | `pos 10 20` | целое число |
| `FloatLit` | `width 1.5` | число с плавающей точкой |
| `StringLit` | `title "A b"` | текст в кавычках |
| `CharLit` | — | смоделирован для совместимости, лексер его не выдаёт |
| `Expression` | `$(1 + 2)` | выражение для потребителя |
| `ExpressionBlock` | `${ var a = 1; a }` | тело инструкций для потребителя |
| `MarkdownLit` | `%{**bold**}` | markdown-тело |
| `Image` | `@(iVBORw0K...)` | данные изображения в base64 |

`;` и переводы строк разделяют команды; `//` и `/* ... */` — комментарии. Всё остальное — фигурные
скобки, доллары, проценты, собаки — только ограничивает одну из форм выше.

## Родство с Tcl

TENN — прямой потомок **Tool Command Language**. Он сохраняет форму команды Tcl, тело в фигурных
скобках как невычисляемое слово и вкус к маленькому языку из одного правила. Подстановку Tcl `[ ... ]`
он заменяет на `${ ... }` / `$( ... )`, а переменные, области видимости времени выполнения и
возвращаемые значения отбрасывает: TENN — декларативные данные со встроенными выражениями, а не
скриптовый язык.

Полное сравнение — в [spec/core.md, раздел 6](spec/core.md#lineage).

## Раскладка репозитория

```
go.mod             модуль Go github.com/haiodo/tenn (пакет tenn лежит в go/)
Package.swift      манифест SwiftPM в корне, чтобы зависимость по URL его находила
spec/              формат: грамматика, AST, печать, профили
  core.md            ядро языка
  profiles/          словари на той же грамматике (scene.md)
go/                пакет Go tenn: импорт github.com/haiodo/tenn/go
typescript/        npm-пакет @haiodo/tenn
swift/             исходники пакета Tenn (путь цели в Package.swift)
conformance/       общие кейсы и канонический AST для всех реализаций
```

Оба манифеста лежат в корне намеренно: SwiftPM ищет `Package.swift` в корне пакета, полученного по
URL, а Go требует, чтобы путь модуля совпадал с репозиторием. Один репозиторий, три тулчейна, один
тег `v0.1.0` для Go и Swift; у npm-пакета своя `version`.

## Использование

**Go** — путь модуля **чувствителен к регистру**; используйте его ровно как написано:

```
go get github.com/haiodo/tenn/go
```

```go
import tenn "github.com/haiodo/tenn/go"

tree, parser := tenn.Parse(`element "Screen" { item A { pos 0 0 } }`)
_ = parser.Errors
```

**TypeScript / Node 24** — пакет лежит в `typescript/`, работает на `.ts` напрямую и не опубликован в
npm registry. Поставить его можно из клона или прилинковать:

```
npm install ../tenn/typescript
```

```ts
import { parse, toStr } from "@haiodo/tenn";

const { tree, parser } = parse('element "Screen" { item A { pos 0 0 } }');
toStr(tree);
```

**Swift** — пакет SwiftPM `Tenn`, macOS 13+:

```swift
.package(url: "https://github.com/haiodo/tenn.git", from: "0.1.0")
```

## Conformance

Три реализации должны строить одно и то же дерево из одного текста. [`conformance/`](conformance/README.md)
хранит общие кейсы, канонический AST в `expected/*.json` и канонический вывод принтера в
`expected/*.tenn`. Каждая реализация проходит один и тот же набор; чтобы добавить кейс, нужен один файл
`.tenn` и перегенерация ожидаемого вывода из эталонной реализации.
